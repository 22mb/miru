# miru

miru（見る）は、AI が生成した Markdown や HTML を、ブラウザでレンダリングした状態のままインラインでレビューするローカルツールです。
本文のテキストを選択するか、要素を `Alt`+クリックすると、その場にコメントを残せます。
すべての処理はローカルで完結し、外部には何も送信しません。

## 特長

- **Bun 製の単一バイナリ**：`bun build --compile` によってランタイムごとバンドルされています。そのため、利用者が Bun などのランタイムを用意する必要はありません。
- **2 種類のアンカー**：アンカーはテキスト範囲（`text`）と要素（`element`）の 2 種類です。元ファイルに軽微な編集が加わってもアンカーは位置を追従し、位置を復元できない場合は `stale` として退避されます。
- **suggestion（修正提案）**：コメントには修正案（置換テキスト）を添付できます。添付した修正案は、そのまま LLM への修正指示として渡せます。
- **人間↔AI レビューループ**：`miru review` は「Approve」ボタンが押されるまで処理をブロックし、未解決のコメントを JSON として出力します。コメントへの返信や解決は、ブラウザとヘッドレス CLI のどちらからでも行えます。また、ファイルが変更されると、開いているページが SSE によってその場で更新されます。ページをリロードせずに文書だけを差し替えるため、スクロール位置やパネルの状態、書きかけの返信はそのまま保持され、変更箇所が一瞬ハイライトされます。キーボードショートカットは、`j` と `k` で移動、`r` で解決、`Esc` で下書きのキャンセルです。
- **セキュリティ**：サーバーは `127.0.0.1` のみにバインドし、`/api/*` へのアクセスは起動ごとに発行されるトークンで保護します（例外は SSE フィードの `/api/events` のみで、このフィードは内容を含まない更新ヒントを配信するだけです）。Host ヘッダーと Origin ヘッダーの検証によって CSRF と DNS リバインディングを防ぎ、厳格な CSP を適用します。さらに、入力 HTML はサーバー側でサニタイズします。デフォルトのサニタイズでは、文書自身の表現（CSS・静的 SVG・メディア）を残しつつ、実行可能なコンテンツをすべて除去します。`--strict` を指定すると、残す対象をタイポグラフィのみに絞れます。なお、レビューパネルは shadow root 内に描画されるため、文書の CSS はレビューパネルに到達しません。
- **完全ローカル**：コメントは `<file>.miru.json` に保存されます。共有機能や外部送信、テレメトリは一切ありません。

## インストール

### Homebrew (macOS / Linux)

```sh
brew tap 22mb/miru
brew trust 22mb/miru   # Homebrew 6.x 以降でサードパーティの tap を使う場合に必要
brew install miru
```

古い Homebrew では `brew trust` は何も実行しない（no-op）ため、このコマンドを含めておけば新旧どちらのバージョンにも対応できます。

### バイナリ

GitHub Releases から、OS とアーキテクチャに応じたバイナリ（win・macOS・linux）をダウンロードして実行します。

### スキル

miru には、「コメント → 修正 → 返信」のループを AI エージェント（Claude Code など）に教える[スキル](skills/miru/SKILL.md)が同梱されています。このスキルは、次のいずれかの方法でインストールできます。

```sh
# gh skill 拡張を使う場合
gh skill install 22mb/miru

# miru 本体を使う場合
miru install
```

どちらの方法でも、`SKILL.md` は `~/.claude/skills/miru/SKILL.md` に配置されます。なお、現在サポートしているのは `claude-code` のみです。

## 使い方

```sh
miru review <file.md|.html>
```

コマンドを実行すると、ブラウザが開きます。
本文のテキストを選択するか、画像やコードブロックなどの要素を `Alt`+クリックして、コメントを追加します。
コメントは、対象ファイルと同じディレクトリにある `<file>.miru.json` に保存されます。

| オプション | 説明 |
|---|---|
| `--port <n>` | ポート番号の指定（デフォルトはランダム） |
| `--no-open` | ブラウザの自動起動を無効化 |
| `--strict` | タイポグラフィのみを残すサニタイズ：文書自身の CSS・SVG・メディアを除去（信頼できないファイル向けに、なりすまし耐性を最大化） |
| `--unsafe-raw` | 入力 HTML のサニタイズを無効化（信頼できる入力に限って使用） |
| `--lang <code>` | レンダリングする文書の `lang` 属性の指定（デフォルトは `en`） |

### コマンド

| コマンド | 説明 |
|---|---|
| `miru review <file>` | ブラウザでレビュー画面を開き、「Approve」が押されるまでブロックしたうえで、`{ approved, comments }` の JSON を stdout に出力（人間↔AI ループの 1 ラウンド分） |
| `miru comments <file> [--json]` | サーバーを起動せずに未解決コメントを表示 |
| `miru comment <file> --reply-to <id> "<body>"` | コメントへの返信 |
| `miru comment <file> --resolve <id>` | コメントを解決済みに変更 |
| `miru next <file>` | コメントがエージェント待ちになるか、ユーザーが承認するまでブロックし、結果を JSON として出力（「`next` → 修正 → 返信」のエージェントループ） |
| `miru install [claude-code]` | 同梱スキルを `~/.claude/skills/miru/SKILL.md` にインストール |
| `miru --version`（`-v`） | 埋め込まれたビルドバージョンを表示して終了 |
| `miru --help`（`-h`） | 使い方を表示して終了（`miru <command> --help` では、そのコマンドのヘルプページを表示） |

### AI エージェントからの利用

[スキル](skills/miru/SKILL.md)をインストールしておくと（[スキル](#スキル)節を参照）、エージェントが `miru review` を実行して JSON を読み取り、修正を適用して返信します。エージェントは、コメントがゼロの状態で承認されるまで、このサイクルを繰り返します。

## 代替ツール

**コードレビュー（git diff）を主な目的とする場合**は、[difit](https://github.com/yoshiko-pg/difit) が適しています。
**よりリッチな機能を求める場合**は、[crit](https://crit.md/) を検討してください。
一方、miru はレンダリングされた Markdown や HTML のインラインレビューに特化した設計であり、生成や共有、PR 連携といった機能は備えていません。
